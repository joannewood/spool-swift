Reviewing Duplicates, Suggestions & Archives

Everything that needs a decision from you lives in one window, separate from your library.

Open it from the toolbar's wrench icon, the Window menu, or ⌘⌥A. It's a real window, not a dialog — you can keep it open alongside your library and switch back and forth freely. Each section's sidebar badge shows how many items are waiting for a decision.

Duplicates

Files with byte-identical content are grouped together. For each group:

  • If a copy lives in a Library (Read-Only) folder, that copy can never be deleted from Spool — it's shown but protected.
  • Otherwise the oldest copy is kept by default; everything else is a candidate for deletion.
  • Clean Up All Duplicates applies that default to every group in one action. Deletions move files to the Trash — recoverable, not permanent.

Suggestions

Two kinds of heuristic-driven suggestions land here: file relationships (duplicate-of, variant-of, derived-from, new-version-of — based on matching content hashes or filename patterns) and project memberships (files that share a folder). Each row can be confirmed or rejected individually, or use the bulk bar at the bottom to check off a subset or accept everything at once. Rejecting is remembered — a suggestion you've turned down won't come back for the same file.

Archives

A .zip, .7z, or .rar found inside a watched folder is only ever surfaced here if it actually contains a recognized 3D-printing file inside — an archive of photos or documents is left alone entirely, never even listed.

  • Pending archives are confirmed (extracted, with the original archive then removed) or rejected (remembered — the exact same file won't be asked about again, but a different file later reusing the same name will be).
  • Unsupported archives are .7z/.rar files found without unar installed (brew install unar) to look inside them — install it and re-open Spool to pick these back up automatically.

Turn on auto-accept in Settings to skip this queue entirely and have every relevant archive extracted the moment it's found.

Status

A live view of the ingestion pipeline — how many files are hashed and rendered, what's currently queued or running, and recent job successes/failures with their errors. Useful when something seems stuck: a large STEP-file backlog, for instance, renders on its own slower lane so it can never block ordinary STL/3MF thumbnails from keeping up.
